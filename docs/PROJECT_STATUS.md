## Goal, scope, and current stage

The 28-week, two-term graduation project aims to let people with severe upper-limb motor impairments use a computer without a conventional mouse/keyboard, with adaptable gaze and intentional inputs, accessible text entry, and eventually safe control of an assistive chair/seating prototype. macOS and Windows are the official desktop targets; development and human gaze testing so far have been on macOS. Linux product support is outside current scope. The Phase 0 exit gate was met **for entering Phase 1**, not for declaring gaze or the product ready. Phase 1 is in progress; its cursor-targeting, latency, tracking-loss, and gaze-stabilization exit evidence is still missing. [Scope](project-scope.md), [roadmap](roadmap.md), [Phase 0 review](phase-0-exit-review.md).

The accepted flow is **Vision → Gaze/Gesture → Intent → Action → Platform/Hardware**. Vision owns camera, landmarks, and vendor-neutral eye features; Gaze owns session calibration and estimation, never OS input. Gestures must not directly click, Intent must not contain OS APIs, and hardware control remains separate from desktop control. The `app` layer coordinates rather than absorbs algorithms. Core interaction must work locally without Internet; normal operation must not upload raw camera/facial/biometric imagery. Physical movement must fail safely and have independent emergency-stop protection. Python 3.12, pytest, Ruff, GitHub Actions, and venv/pip are accepted tooling. See [architecture](architecture.md), [ADR-001](decisions/ADR-001-local-first-processing.md), [ADR-002](decisions/ADR-002-target-platforms.md), [ADR-003](decisions/ADR-003-modular-architecture.md), [ADR-004](decisions/ADR-004-python-runtime-and-quality-tooling.md), and [safety requirements](requirements.md#3-safety-requirements-safe).

## Vertical-gaze problem: diagnostic conclusions

The current primary feature is `binocular_vertical_local_axis`, and the current mapping is a session-fitted, independent-linear baseline. Calibration and held-out data reveal substantial vertical-coordinate error despite successful capture/tracking. The studies below use **Çağrı-only**, separate controlled sessions unless stated otherwise; none explains Fatih's near-flat output or identifies a physical cause.

In Session B, calibration-to-held-out center-row feature difference ~−0.00464 mapped to ~−0.203 y, near signed held-out y bias −0.2107. | Feature movement is a strong explanation for that session's bias, but its **cause is unknown**; center-row layouts/times differ. ### Current hypotheses and future candidates — not decisions

- **Supported problem, unknown cause:** both calibration-fit residual and later same-target vertical-feature variability contribute to error. #52 strengthens the repeat-variability observation; it does not prove time drift, a general X effect, eyelid cause, or head-pose cause. The coarse face-center-y measure cannot distinguish translation from pitch. [#46](../experiments/vertical_drift_diagnostics/RESULTS.md), [#48](../experiments/vertical_error_decomposition/RESULTS.md), [#52](../experiments/vertical_position_variability/RESULTS.md).
- **Open team decision on any next vertical-stabilization step:** two fresh live runs of the fixed CENTER anchor reduced held-out vertical error, but the candidate remains experimental and no production vertical correction is selected. Three subsequent controlled live sessions showed both differing calibration sensitivity and differing same-target feature movement; neither mechanism alone establishes vertical stability or a physical cause. Cross-user reliability remains unresolved. Any candidate handling (quality gating, short-window aggregation, recalibration, geometry or mapping change) needs its own approved issue and held-out/live evidence. Fatih's near-flat vertical run needs separate cross-user diagnosis, not an assumed explanation from Çağrı's sessions. [Controlled live sensitivity](../experiments/vertical_sensitivity_live_study/RESULTS.md), [Fixed CENTER live validation](../experiments/fixed_center_live_validation/RESULTS.md), [#52](../experiments/vertical_position_variability/RESULTS.md), [PR #43](https://github.com/cagriinan46/eye-tracker/pull/43).
- Do **not** repeat parameter-tuning of 100–300 ms smoothing or the Experiment 005 blink gate against the same three runs without new evidence; do not adopt fixed global thresholds, an ad-hoc y offset, unlabeled head compensation, or piecewise row anchors based on calibration fit alone. Do not treat 21/21 spatial ordering or low MAE from near-center predictions as full accuracy. Do not infer a universal glasses effect, select MediaPipe/OpenCV forever, or move to cursor/click/gesture work on the assumption that vertical stability is solved. [005](../experiments/005-vertical-stabilization/RESULTS.md), [#50](../experiments/vertical_mapping_evaluation/RESULTS.md), [#52](../experiments/vertical_position_variability/RESULTS.md).

## Privacy, hardware, and immediate GitHub state

The committed harnesses do not save raw camera images/video; derived human CSV/JSON files stay local under Git-ignored `.venv/` and may still be sensitive. A separate **unresolved third-party telemetry question** exists: MediaPipe logged `portable_clearcut_uploader` “failed send” in #46 and #52. The attempted payload and network behavior are unknown. Local processing and no harness upload path do **not** prove the library made no outbound attempt or uploaded no biometric data; investigate separately before asserting full normal-operation compliance with [ADR-001](decisions/ADR-001-local-first-processing.md). [#46 results](../experiments/vertical_drift_diagnostics/RESULTS.md), [#52 results](../experiments/vertical_position_variability/RESULTS.md).

Hardware actually tested: Macs' cameras (Çağrı used runtime index 1; Fatih used index 0 in PR #43) and local Face Landmarker model. No assistive chair/seating actuator, hardware controller, emergency stop, macOS/Windows OS-input adapter, or Windows production validation has been delivered. Camera indices must remain runtime-configurable. The Phase 1 pipeline outputs gaze estimates or explicit unavailability, **not cursor movement**.
