# Phase 0 Exit Review

## Purpose

Assess whether [Phase 0 — Technical Validation](roadmap.md#phase-0--technical-validation) has supplied quantitative evidence of baseline gaze feasibility, its main limitations, and a defensible next implementation direction. This is a gate recommendation for human review, not approval of a production algorithm, dependency, or change to the roadmap.

## Phase 0 Questions

| Question | Evidence-based answer |
| --- | --- |
| Camera acquisition | **Validated under tested conditions:** the development Mac's built-in camera delivered 303 frames at 1920 × 1080 over 10.026 s (30.22 effective FPS), with zero failed reads. Camera index 0 instead selected a paired iPhone, so device identity cannot be inferred from index alone. [Experiment 001](../experiments/001-camera-baseline/RESULTS.md) |
| Face/eye landmarks | **Validated under tested conditions:** a controlled face-present run using experimental MediaPipe 0.10.35 produced face detections and blendshape output in all 864 processed frames, with 478 landmarks, zero tracking-loss events, and 25.07 effective processing FPS. MediaPipe 1.0.1 caused a native SIGABRT at model initialization on the tested macOS ARM64/Python 3.12 setup. Neither observation selects a production framework. [Experiment 002](../experiments/002-face-landmarks/RESULTS.md) |
| Horizontal gaze information | **Validated under tested conditions:** normalized binocular iris position separated LEFT/CENTER/RIGHT in the guided single-user study, with non-overlapping reported raw horizontal ranges and reasonably repeatable trial means. [Experiment 003](../experiments/003-gaze-features/RESULTS.md) |
| Vertical gaze information | **Promising, not final:** binocular local-eye-axis geometry preserved UP < CENTER < DOWN mean ordering across three runs, including normal eye opening with glasses. Frame ranges still overlapped, trial means varied, and absolute values shifted between runs. [Experiment 004](../experiments/004-vertical-gaze/RESULTS.md) |
| Blink/eyelid contamination | **Unresolved for production:** local-axis variation was strongly associated with blink and eye-opening signals; correlation does not establish cause. Short smoothing and conservative blink rejection reduced some jumps, but no tested method consistently improved overlap or repeatability across three runs. No production filter or blink threshold is validated. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md) and [005](../experiments/005-vertical-stabilization/RESULTS.md) |
| Session drift and calibration | **Supported direction:** Experiment 004's CENTER local-axis mean shifted from about -0.0471 to -0.0409 to -0.0347 across runs, arguing against fixed global values. A same-session 3 × 3 calibration followed by held-out validation supported approximate mapping; cross-session reuse or a required point count was not tested. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md) and [006](../experiments/006-2d-gaze-mapping/RESULTS.md) |
| Held-out 2D mapping | **Validated as limited feasibility:** the successful single-user Mac rerun had 897 usable samples, nine calibration targets, and 16 held-out trials at distinct interstitial locations. Both simple candidates achieved 21/21 descriptive spatial-order comparisons on each axis. Median window-pixel-equivalent error was 69.38 px (independent linear) and 62.44 px (affine 2D), relative to a 1200 × 700 target-window image area—not verified hardware display pixels. Mean vertical absolute error (0.0699/0.0721 normalized) exceeded horizontal (0.0277/0.0301). This is approximate feasibility, not pixel-perfect or production accuracy. [Experiment 006](../experiments/006-2d-gaze-mapping/RESULTS.md) |
| Latency / real-time viability | **Partly measured:** Experiment 001 measured frame acquisition (33.084 ms mean, 40.862 ms p95); Experiment 002 measured Face Landmarker inference calls (6.773 ms mean) and whole-run processing FPS. These separate measures justify continued interactive research, **not** an end-to-end camera-to-gaze, cursor, or user-perceived latency claim. [Experiments 001](../experiments/001-camera-baseline/RESULTS.md) and [002](../experiments/002-face-landmarks/README.md) |
| Local-first / privacy | **Demonstrated for these experiments:** camera processing, feature extraction, and mapping ran locally; scripts did not need cloud processing or save raw frames/video. Model download was a separate setup step. Derived numeric CSVs may still be sensitive and remain local/Git-ignored; this does not validate production privacy controls. [Experiments 002](../experiments/002-face-landmarks/README.md), [005](../experiments/005-vertical-stabilization/README.md), [006](../experiments/006-2d-gaze-mapping/README.md), and [ADR-001](decisions/ADR-001-local-first-processing.md) |
| Cross-platform status | **Not tested beyond macOS:** human camera and gaze evidence comes from the development Mac. Windows remains an official target, but Windows vision, input control, and packaging have not been validated. [Experiment 006](../experiments/006-2d-gaze-mapping/RESULTS.md), [ADR-002](decisions/ADR-002-target-platforms.md), and [Phase 8](roadmap.md#phase-8--windows-platform-support) |

## Evidence Reviewed

The governing sources were [project scope](project-scope.md), [requirements](requirements.md), [architecture](architecture.md), [roadmap](roadmap.md), and [accepted ADRs](decisions/). The six completed experiment protocols and results were [001 camera capture](../experiments/001-camera-baseline/README.md), [002 face landmarks](../experiments/002-face-landmarks/README.md), [003 directional eye features](../experiments/003-gaze-features/README.md), [004 vertical geometry](../experiments/004-vertical-gaze/README.md), [005 temporal stabilization](../experiments/005-vertical-stabilization/README.md), and [006 2D mapping](../experiments/006-2d-gaze-mapping/README.md), together with each experiment's `RESULTS.md`. The successful Experiment 006 derived CSV is local and Git-ignored; its reported summary and per-trial predictions are preserved in [its results](../experiments/006-2d-gaze-mapping/RESULTS.md). Earlier reports rely partly on supplied aggregates rather than committed frame datasets.

## Validated Findings

- Controlled short runs on the development Mac demonstrated usable camera frames, face landmarks, and local numerical feature extraction without raw-image persistence. These are *tested-environment* findings, not device-wide reliability guarantees. [Experiments 001](../experiments/001-camera-baseline/RESULTS.md), [002](../experiments/002-face-landmarks/RESULTS.md), and [003](../experiments/003-gaze-features/RESULTS.md)
- Horizontal directional separation was clear, and the existing horizontal/local-axis vertical feature pair supported approximate **same-session** held-out 2D mapping. The latter result is stronger than calibration-fit error because its validation targets were not used for model fitting. [Experiments 003](../experiments/003-gaze-features/RESULTS.md) and [006](../experiments/006-2d-gaze-mapping/RESULTS.md)
- The vertical feature's mean ordering repeated under several tested conditions, but vertical error remains the main coordinate-accuracy bottleneck. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md) and [006](../experiments/006-2d-gaze-mapping/RESULTS.md)

## Findings That Remain Experimental

- MediaPipe 0.10.35 and OpenCV worked as experiment-specific tools on the Mac; [ADR-004](decisions/ADR-004-python-runtime-and-quality-tooling.md) explicitly leaves production computer-vision dependencies undecided. MediaPipe 1.0.1's observed SIGABRT warrants compatibility review before any future version change. [Experiments 001](../experiments/001-camera-baseline/RESULTS.md) and [002](../experiments/002-face-landmarks/RESULTS.md)
- The 3 × 3 calibration layout, independent linear and affine mappings, and experimental blink-quality gate were feasibility choices, not approved production methods. The two mappings both retained held-out ordering, and Experiment 006 did not establish a production winner. [Experiment 006](../experiments/006-2d-gaze-mapping/README.md) and [results](../experiments/006-2d-gaze-mapping/RESULTS.md)
- No temporal or blink-aware method was consistently superior across the three prior human runs; the inconclusive result should not be converted into a mandatory smoothing stage. [Experiment 005](../experiments/005-vertical-stabilization/RESULTS.md)

## Unresolved Risks

- **Vertical variability and eyelids:** raw vertical ranges overlap and blink/eye-opening measures covary with the local-axis feature. Filtering may remove real gaze information; the causal source and suitable live handling remain unproven. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md) and [005](../experiments/005-vertical-stabilization/RESULTS.md)
- **Position and session changes:** absolute vertical values shifted between runs; controlled head-motion, lighting, distance, glasses, camera placement, and recalibration-frequency studies are absent. The simple head-center-y proxy does not isolate pitch from translation. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md) and [006](../experiments/006-2d-gaze-mapping/RESULTS.md)
- **Interaction quality:** no end-to-end latency, live gaze-transition delay, tracking-loss recovery, cursor-targeting success, false activation, comfort, or accessibility usability was measured. These belong to subsequent phases, not to claims made from Phase 0. [Experiments 002](../experiments/002-face-landmarks/README.md), [005](../experiments/005-vertical-stabilization/RESULTS.md), [006](../experiments/006-2d-gaze-mapping/RESULTS.md), and [Phase 1 exit criterion](roadmap.md#phase-1--gaze-control-core)
- **Evidence breadth and reproducibility:** human gaze studies involved one user and short controlled runs. Experiment 006's successful numerical CSV is local/ignored, while earlier studies often preserve aggregate results only; independent replication by reviewers is limited. [Experiments 003](../experiments/003-gaze-features/RESULTS.md), [004](../experiments/004-vertical-gaze/RESULTS.md), and [006](../experiments/006-2d-gaze-mapping/RESULTS.md)

## Architecture Decisions Supported by Evidence

- Retain the already accepted Python 3.12 runtime for Phase 1; all Phase 0 tooling used the Python-first environment. This confirms suitability for the tested experiments, not final performance on every platform. [ADR-004](decisions/ADR-004-python-runtime-and-quality-tooling.md) and [Experiments 002](../experiments/002-face-landmarks/RESULTS.md) and [006](../experiments/006-2d-gaze-mapping/RESULTS.md)
- Use the tested OpenCV camera path and MediaPipe 0.10.35 landmark path as **prototype candidates** if explicitly approved in a Phase 1 task. Seed the gaze core with the tested normalized binocular horizontal and local-axis vertical features; keep them behind project-level vision/gaze boundaries so alternatives remain possible. [Experiments 001](../experiments/001-camera-baseline/RESULTS.md), [002](../experiments/002-face-landmarks/RESULTS.md), [003](../experiments/003-gaze-features/README.md), [004](../experiments/004-vertical-gaze/README.md), and [architecture](architecture.md#4-feature-extraction)
- Plan for session/user-specific calibration rather than fixed global feature thresholds. Preserve the approved separation of vision → gaze → intent → actions → platform/hardware; this boundary is an existing architectural decision, **not** a new decision created by these experiments. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md), [006](../experiments/006-2d-gaze-mapping/RESULTS.md), [architecture](architecture.md#15-dependency-direction), and [ADR-003](decisions/ADR-003-modular-architecture.md)

## Decisions NOT Yet Justified

The evidence does **not** justify permanently selecting OpenCV, MediaPipe, a Face Landmarker version, a gaze-mapping model, a fixed calibration-point count, a smoothing/blink threshold, head-pose compensation, or global gaze thresholds. It also does not select a confidence algorithm, OS input API, GUI, or packaging strategy. These remain governed by [architecture TBDs](architecture.md#22-current-architectural-tbds) and [ADR-004](decisions/ADR-004-python-runtime-and-quality-tooling.md), with future major decisions requiring human review under [AGENTS.md](../AGENTS.md#human-controlled-decisions). [Experiments 002](../experiments/002-face-landmarks/RESULTS.md), [005](../experiments/005-vertical-stabilization/RESULTS.md), and [006](../experiments/006-2d-gaze-mapping/RESULTS.md) show why a prototype result alone is insufficient.

## Phase 0 Exit Criteria Assessment

The [roadmap's explicit exit criterion](roadmap.md#phase-0--technical-validation) is quantitative evidence of baseline gaze feasibility and limitations, sufficient to choose the next implementation direction. The statuses below separate that gate from roadmap *key questions* that need later investigation.

| Criterion or key question | Status | Evidence / implication |
| --- | --- | --- |
| Quantitative baseline gaze feasibility on standard consumer-camera hardware | **Met** | Measured capture, landmark throughput, directional features, and separate held-out 2D mapping on the development Mac. [Experiments 001](../experiments/001-camera-baseline/RESULTS.md), [002](../experiments/002-face-landmarks/RESULTS.md), [003](../experiments/003-gaze-features/RESULTS.md), [006](../experiments/006-2d-gaze-mapping/RESULTS.md) |
| Main technical limitations identified and measured | **Met** | Vertical overlap/eyelid association, cross-session offsets, and inconclusive filtering are documented; held-out x/y error asymmetry is measured. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md), [005](../experiments/005-vertical-stabilization/RESULTS.md), [006](../experiments/006-2d-gaze-mapping/RESULTS.md) |
| Enough information to choose the next implementation direction | **Met** | A bounded reusable vision → features → session calibration → normalized gaze-result slice is supported; a production algorithm/filter is not selected. [Experiment 006](../experiments/006-2d-gaze-mapping/RESULTS.md), [architecture](architecture.md#15-dependency-direction), and [Phase 1 goal](roadmap.md#phase-1--gaze-control-core) |
| Signal stability under normal variation | **Partially Met** | Three vertical runs and a held-out rerun expose variation, but realistic lighting, distance, device, and user variation remain untested. [Experiments 004](../experiments/004-vertical-gaze/RESULTS.md) and [006](../experiments/006-2d-gaze-mapping/RESULTS.md) |
| Isolated effect of head movement | **Not Met** | Only an imperfect head-center proxy and stable-head instructions were used; no controlled head-motion comparison or compensation result is reported. [Experiment 004](../experiments/004-vertical-gaze/RESULTS.md) |
| Direct pointer-control viability and need for coarse target correction | **Not Met** | The roadmap raises this as a Phase 0 key question, but Experiment 006 did not move a cursor or evaluate target selection. It remains a Phase 1 research risk rather than evidence to assert either interaction design. [Experiment 006](../experiments/006-2d-gaze-mapping/README.md) and [roadmap](roadmap.md#phase-0--technical-validation) |
| End-to-end cursor latency and Windows behavior | **Not Required for Phase 0** | Phase 1 evaluates cursor targeting and latency; Windows support is a later phase. Neither was measured by these experiments. [Phase 1](roadmap.md#phase-1--gaze-control-core), [Phase 8](roadmap.md#phase-8--windows-platform-support), and [Experiment 006](../experiments/006-2d-gaze-mapping/README.md) |

**Gate assessment: the explicit Phase 0 exit criterion is met, with material risks carried forward.** This is not a claim that every roadmap key question is settled or that any functional product requirement has been delivered. [Roadmap](roadmap.md#phase-0--technical-validation)

## Phase 1 Entry Recommendation

**Recommend entry into Phase 1 with a narrow, measured first slice.** The held-out same-session mapping result is sufficient to start turning the experimental signal path into a reusable core. Phase 1 must still establish live transition behavior, controlled failure/recovery, end-to-end latency, and eventually cursor-targeting performance before its own exit criterion can be met. Do not treat the Experiment 006 median window-pixel-equivalent errors as cursor accuracy or general accessibility performance. [Experiment 006](../experiments/006-2d-gaze-mapping/RESULTS.md), [Phase 1 exit criterion](roadmap.md#phase-1--gaze-control-core), and [NFR-003](requirements.md#2-non-functional-requirements-nfr)

## Proposed First Phase 1 Work

The smallest proposed production-oriented vertical slice is **camera frame → landmark extraction → normalized horizontal and local-axis vertical features → session calibration boundary → normalized gaze estimate or explicit unavailable state**, with measurements at the boundaries. Keep feature extraction in vision and calibration/mapping in gaze as required by [architecture sections 3–5](architecture.md#3-vision-layer) and [ADR-003](decisions/ADR-003-modular-architecture.md). Use the existing experimental formulas only as starting candidates, not copied-in architecture decisions. No OS cursor movement, clicks, wink/dwell commands, semantic gaze, hardware, Windows adapter, or advanced GUI belongs to this first slice. This is a proposal for the human team to turn into a separate, approved Phase 1 issue, **not** an implementation authorization. [Experiments 003](../experiments/003-gaze-features/RESULTS.md), [004](../experiments/004-vertical-gaze/RESULTS.md), [006](../experiments/006-2d-gaze-mapping/RESULTS.md), and [roadmap](roadmap.md#phase-1--gaze-control-core)

The [roadmap](roadmap.md) defines phases but has no status field to become stale; it was therefore not changed in this review.
